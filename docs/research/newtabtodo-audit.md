# NewTabTodo 0.2.0 能力与数据链路审计

日期：2026-10-26。用途：为独立实现的 OhMyNewTabTodo 确定第一版基线，不是产品实现设计或开工授权。

范围更新（2026-10-27，用户确认）：第一版优先本机使用及导入导出，暂不考虑 Chrome 跨设备自动同步。下表 F30 保留为原版能力记录，已移出当前第一版范围；同一浏览器多标签页一致性仍需处理。数据层已选择原版业务结构 + chrome.storage.local，详见[最终设计](../superpowers/specs/2026-10-27-v1-design.md)。

## 结论与证据边界

已完成本机 0.2.0 发布包的主要交互、数据访问、导入导出、后台和外部接口代码审计，以及 11 项隔离行为验证。未操作真实浏览器中的删除、导入或清空，未运行真实跨设备同步或完整 UI 回归。

- **代码确认**：在当前发布包中存在对应入口和逻辑，不能等同于真实浏览器端到端通过。
- **隔离复现**：执行本机原始函数，使用人工数据和模拟存储；能证明该函数在给定条件下的行为。
- **真实证据**：用户的导出结构及 F12 报错；内容未写入本文。
- **待实测**：视觉细节、实际浏览器事件顺序、同步延迟、跨设备冲突和外部服务可用性。

可重复验证脚本：`scripts/audit-installed-newtabtodo.cjs`；结果：`audit-results.json`。脚本仅在运行时读取用户提供的本机安装包，不包含原版实现；不访问真实浏览器存储，不发送网络请求。

### 设置默认值

启用：声音、允许隐藏看板、链接格式化、完成卡片变暗、时钟、固定时钟。

关闭：隐藏描述、隐藏完成卡片、紧凑模式、24 小时制。

默认显示 Google 与 YouTube 搜索入口；隐藏 Bing 与 DuckDuckGo。

默认对象还含 collectAnonymousUsageData=true；未发现对应设置控件，统计发送路径未见使用该值作为开关。这不是新版应继承的用户功能。

## 数据链路

### 初始化

1. Provider 以空任务数据及内置链接作为初始状态。
2. 检查 isMigrated；必要时将旧 app_todos 转换为独立 card-/board- 键，备份旧对象并尝试删除旧键。
3. 读取全部任务键和 app_bookmarks。
4. 有 boardOrder 时加载任务，否则使用空任务模型；书签缺失或为空数组时显示内置链接。
5. 设置单独读取并缓存到 window._appOptions；主题从 localStorage 读取。
6. 非首次状态变化触发保存 effect。由于 React 的对象比较与空值分支，不能假设显示了内置链接就必定写入 app_bookmarks。

关键区别：缺失字段、显式空数组和初始化默认值混在了一起。新版应区分首次使用和用户主动清空。

### 编辑与保存

卡片/看板操作修改 React 页面快照；状态变化后调用 setData，将该快照的所有卡片、看板及 boardOrder 再写入 sync。

没有每次操作的版本校验或事务式冲突检查。setData 捕获写入错误并返回错误对象，页面保存 effect 未检查这个返回值。UI 的更新不证明存储成功。

编辑卡片时表单重新组装对象，处理函数先移除旧卡片再添加新对象。表单未保留 createdAt、tags、history 等原有字段；这是静态发现，完整表单提交尚待浏览器验证。新版必须明确编辑可见字段时如何保留不可见字段。

### 删除与残留

删除处理函数从页面对象中移除卡片/看板，然后仍调用 setData。setData 只 set 剩余对象，不 remove 被删除的键。因此读取全部存储或导出时仍可能找到旧对象。

隔离执行真实删除处理函数后，确认：删除看板使页面数据变空，但存储仍保留原看板及两张卡片；删除单张卡片使看板不再引用它，但卡片键仍存在。

这能解释用户文件中“对象存在、顺序中不存在”的一种来源，但没有用户历史操作记录，不能断定其具体来源。

### 多页面和同步

应用主包未找到 storage.onChanged 监听或 visibilitychange 后重新读取逻辑；后台脚本仅处理安装/按钮打开新标签页。每个页面持有自己的快照。

隔离验证：页面 A 改卡片 A 并保存，持有旧快照的页面 B 改卡片 B 并保存，卡片 A 的修改被覆盖。这里证明的是保存算法的并发风险，不是已经测量真实跨设备冲突。

Chrome 会同步 storage.sync，但这不等于应用具备冲突合并、同步完成确认或当前页面实时刷新。新扩展有自己的身份与存储，不能直接沿用原扩展账号下的数据空间；首次迁移仍需文件或单独授权的本机救援路径。

### 导入与刷新

导入先读取当前任务和书签，校验文件，再重建所有对象 ID，追加数据，先写书签再写任务。两次写入不具有整体事务性，且错误对象被忽略。

成功提示显示后调用关闭设置回调；设置关闭会记录统计，并在统计回调中 reload 页面。因而原版有刷新路径，不能笼统说“导入成功后完全不刷新”；但刷新与统计存储耦合，其他已打开页面依然可能持有旧快照。

### 导出

读取当前存储后，按固定白名单拣选字段。包括不在 boardOrder 中的残留看板，以及不再被可见看板引用的卡片。未包含完整设置、主题，也会丢弃未知字段。

| D13 | 导出缺少设置并过滤未知字段 | 代码确认 + 未知字段隔离复现 | 完整备份格式独立于旧格式导出 |

## 隐私与外部依赖

发布包包含统计、通知、反馈 API：

- 操作事件元数据中存在卡片对象、标题、描述等字段；事件缓存在 app_analytics，经 q 写入同步存储，批量发送到作者统计接口。发送代码有时间节流，但未见 collectAnonymousUsageData 的开关判断。
- 反馈请求体包含姓名、邮箱、反馈内容以及当前完整任务数据。
- 通知接口向页面返回通知文本；需独立评估其渲染方式。
- 本次没有向任何这些接口发送请求，也没有抓取实际用户上传流量；上述是客户端代码可达路径，不能断言服务器收到或保留了什么。

新版应把核心任务功能与这些作者服务解耦。建议默认不收集内容，反馈使用显式可审查的诊断信息；是否提供任何遥测另行讨论。
