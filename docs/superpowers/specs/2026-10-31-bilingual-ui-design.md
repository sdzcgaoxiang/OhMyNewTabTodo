# 中英文界面切换设计

## 意图与范围

让首次安装和升级后的用户看到英文界面，并在新标签页首页直接切换为简体中文。切换应覆盖看板、卡片、设置、导入导出、确认窗口、日期、状态、错误和无障碍名称；用户写入的看板名、卡片内容、标签、书签和导入数据保持原文。现有中英文文档继续成对维护。

## 已有情况与约束

当前扩展界面只有中文；中英文 README 和功能说明已经存在。首页顶部有主题、常用链接和设置，适合放置语言入口。所有持久化修改由后台写入，旧 `app_state` 和历史完整备份没有语言字段。数据导入、未知字段、旧 ID、恢复点和多标签页行为不能因语言切换受损。Node.js 22.12+，不新增运行时依赖。当前工作区的两处 CI 工作流改动属于既有修改，实施时保留。

## 方案

1. **首页顶部 `EN / 中文` 双选按钮（采用）**：当前语言直观可见，点击一次切换；宽屏和窄屏均可用。
2. 单个循环切换按钮：占地更少，但用户不易判断按钮表示当前语言还是目标语言。
3. 下拉菜单：容易扩展更多语言，但只有两种语言时增加一次操作。

文案采用仓库内的英文、中文词条表和带参数的格式化函数。UI 渲染时按当前语言取词条；业务层产生可序列化的错误/警告标识与参数，由 UI 决定展示语言。不要用文字替换去翻译错误，也不根据用户输入猜测语言。

## 行为

- 默认语言固定为英文，不依赖浏览器语言。已有状态或旧完整备份缺少语言字段时按英文读取；读取本身不写回。手动切换后通过后台写入并在新标签页、刷新及其他已打开的标签页保持一致。保存失败时保留原语言并用原语言提示。
- 语言作为界面偏好进入完整备份和恢复点；替换导入新版完整备份时恢复其语言，导入旧备份时保留当前语言；合并、副本、原版格式导入均保留当前语言。旧格式导出不增加语言字段。继续使用现有备份格式版本，读取时兼容缺失字段。
- `EN / 中文` 放在首页顶部操作区，不藏在设置里。按钮有明确的当前状态与可访问名称；更新 `html lang`。切换语言不重置当前看板、编辑草稿、导入预览或搜索内容。
- 整个扩展的静态界面文案、动态计数、相对日期、日期格式、提示、确认与文件预览警告均按选择显示。未知优先级值、异常原始错误和用户内容原样保留；不存在对应英文文案的内部错误给出英文兜底提示，不能把中文内部错误直接暴露在英文界面。
- 新建看板、恢复孤立卡片等操作生成的名称按创建时语言写入，之后视为用户数据，不随界面切换改名。旧恢复点的内置中文标签在显示时识别为对应的系统标签并翻译，存储值不改写；未知标签保持原文。
- Chrome 扩展的名称保持 `OhMyNewTabTodo`；`manifest` 描述和操作标题使用 Chrome 官方 `_locales`，默认英文。Chrome 扩展管理页元数据跟随 Chrome 界面语言，它不能随首页按钮即时切换，这一点在文档中说明。
- 语言切换不新增网络请求、账户、同步或权限。

## 验收与发布边界

- 测试先行：旧状态/旧备份读入、偏好持久化、跨标签更新、导入恢复语义、双语日期/错误、首页切换、键盘与窄屏布局都用合成数据验证。
- 本地执行 `npm run check` 与 `npm run package`；检查安装包含 `_locales`，在 Playwright 扩展中覆盖英文默认和中文切换。CI 在推送和 PR 上运行同样的检查；只有版本 tag 触发发布工作流。
- 同步更新中英文 README、功能说明、CHANGELOG、受影响截图与新版本验收记录。实施阶段先记入 Unreleased；按 `docs/releasing.md` 决定正式版本号、tag 与 Release，不在功能完成时自动发布。
