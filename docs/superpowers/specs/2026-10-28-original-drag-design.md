# 原版拖拽体验迁移设计

日期：2026-10-28。目标是补齐 NewTabTodo 0.2.0 已有的卡片和看板拖拽反馈，不增加新的拖拽功能。依据为 Mozilla 官方发布的 NewTabTodo 0.2.0 扩展包中的界面代码和样式；该包仅用于本地审计，不进入本仓库。Chrome 版此前审计的文件哈希不同，因此实际视觉验收仍以用户使用的 Chrome 原版为准。

## 原版行为

- 原版使用 `react-beautiful-dnd` 风格的 `DragDropContext`、`Droppable` 和 `Draggable`。卡片列表是纵向放置区，全部看板共用一个横向放置区；看板标题栏是拖动手柄。
- 两种放置区都渲染库提供的 `placeholder`。拖动时周围项目让位，卡片经过列表时列表背景改变，拖起的卡片加阴影。没有发现应用自己绘制的独立拖动浮层。
- 松手后检查目标是否存在、位置是否变化，再按源和目标索引更新顺序。卡片可在同列排序或跨列移动；看板可横向排序。拖出有效放置区时不更新数据。
- 隐藏完成项设置启用时，完成卡片不可拖动；放置位置受到完成项区域的约束。此处须用实际浏览器验证边界，不照搬原版的数据索引缺陷。

## 实现选择

考虑了两条路径：继续扩展当前 HTML 原生拖放，需要自行实现占位尺寸、邻项位移、滚动容器定位和键盘事件；换成同一组件模型的维护分支 `@hello-pangea/dnd`，可沿用原版的拖拽结构与占位机制。推荐后者。原始 `react-beautiful-dnd` 已归档，维护分支支持项目使用的 React 19；dnd-kit 需要重新定义交互模型，适合新增行为，不适合此次按原版迁移。

## 代码边界

- 在 `App.tsx` 的看板区域放置一个 `DragDropContext`。看板外层是横向 `Droppable`，每个看板是 `Draggable`，标题栏承载 `dragHandleProps`；卡片列表是纵向 `Droppable`，卡片是 `Draggable`。原有原生 `draggable`、`onDragOver` 和 `onDrop` 处理移除，以免两套事件相互干扰。
- 把提供的引用、拖动样式和占位节点放在对应容器；仅补足原版已有的悬停背景和拖起阴影。现有卡片编辑、点击、复选框与移动按钮保留。
- `onDragEnd` 只提交一次 `board.move` 或 `card.move` 给现有后台写入器；拖动预览由拖拽库处理，不在每次经过项目时保存。取消拖动不提交。保存失败时显示现有错误提示并恢复持久化顺序。
- 由可见卡片列表计算目标位置，再映射到完整 `cardIds` 索引；隐藏完成项时不允许把未完成卡片插到不可见完成项之后。看板的可见索引同样映射到完整 `boardOrder`，避免隐藏看板影响排序。

## 验收

浏览器测试覆盖：同列上下排序、跨列排序、空列放置、横向看板排序、拖出区域取消、隐藏看板与隐藏完成项的索引、刷新后顺序、拖动时占位和邻项让位。另在隔离浏览器中人工比较原版与新版的拖起阴影、列表悬停背景及滚动时的反馈。测试数据只用合成卡片，不触碰用户原版数据。
