# 外部工具读取接口：本地 JSON 文件

日期：2026-11-04；2026-11-09 补充 CLI 与 Skill。

状态：用户已确认固定 JSON 文件自动更新设计；实现与验收进行中。

设计审阅：独立审阅未发现影响实施规划的未决问题。此结论不代表已经验证浏览器文件访问能力。

## 意图与已确认需求

让未来自行开发的程序、脚本和 AI 工具读取待办，同时保持插件可以独立使用。
不要求安装桥接程序、不启动独立服务、不引入账号或云端。
浏览器完全退出后仍可读取最后一次成功写出的数据。
用户接受待办页面未打开时不自动更新，重新打开页面后自动更新。
用户已选择固定 JSON 文件自动更新；动态推送留待未来有具体工具需求时另行设计。

## 目标、非目标与约束

- 提供明确、版本化、可由普通文件读取方式消费的只读数据契约。
- 导出已持久化的看板和任务，包括已完成任务、隐藏看板及排序关系。
- 首次由用户选择文件并授权；权限有效时，页面打开与持久化变化自动触发刷新。
- 导出失败不影响待办保存，不读取外部文件来修改待办，不修改旧 ID 或未知业务字段。
- 不提供 HTTP 监听端口、MCP 服务、外部写入、跨设备同步、常驻进程或后台文件刷新承诺。
- 现有完整备份与旧格式导入导出继续保留；本接口文件不是完整备份，也不新增对应导入模式。
- 外部工具须具有该文件的访问权限。AI 是否可以直接读取取决于该工具的本地文件能力和授权。
- 文件是明文数据。关闭功能或卸载扩展不删除已经生成的文件。

## 方案比较与选择

| 方案                           | 优点                                                       | 代价与边界                                                        | 决定                               |
| ------------------------------ | ---------------------------------------------------------- | ----------------------------------------------------------------- | ---------------------------------- |
| 用户授权固定文件，页面自动更新 | 无额外程序；用户选择位置；外部工具使用稳定路径；无重复下载 | 依赖 File System Access API；权限可能需恢复；页面关闭时不承诺刷新 | 用户选择，第一版实现               |
| 下载 API 覆盖固定文件          | 无额外程序；可以在下载目录内输出固定文件                   | 需要 downloads 权限；路径受下载目录限制；下载设置和记录影响体验   | 仅作为比较，不在第一版加入隐藏回退 |
| 插件直接向小工具推送           | 工具可以自行处理动态数据；不必另装通用桥接程序             | 工具需要运行并提供接收接口；新增网络权限、身份验证与失败补偿      | 后续独立需求                       |

推荐固定文件的原因是其直接覆盖离线读取和未来工具接入，且不改变插件的独立运行方式。
自动下载、HTTP、MCP 和动态推送均不属于本次交付。

## 用户可见行为

### 开启与选择文件

在设置的导入 / 导出区域增加“外部工具读取”功能，默认关闭。
提供“选择数据文件并开启”，通过用户点击调用打开文件选择器，用户先创建专用空白文件（例如 `todos.json`）；选择器本身不会截断已有文件。
建议使用专用文件，不覆盖现有完整备份；文件确认后会自动替换其内容。
只申请所选文件的权限，不要求选择整个文件夹，也不要求访问浏览器配置目录。

选择取消不改变现有配置和文件。重新选择文件时，旧配置保留至新文件授权、首次写入和配置切换成功。
失败时不把新文件显示为当前成功连接目标；若新文件已经写出但配置未保存，明确报告“文件已写出，连接未保存”。
跨文件替换不是事务，不承诺自动删除已写出的新文件或回滚系统操作。

正常情况下，首次选择成功后立即读取当前持久化数据并导出。
界面显示文件名、连接状态、最后成功导出时间和数据修订号。
API 不保证可取得完整操作系统路径，因此不在界面伪造路径；使用文档说明外部工具应指向用户刚选择的位置。

### 自动与手动刷新

| 触发或场景                                   | 行为                                                           |
| -------------------------------------------- | -------------------------------------------------------------- |
| 首次开启成功                                 | 立即生成一份完整接口文件                                       |
| 任一待办页面打开或重新加载                   | 配置启用且权限有效时，立即从后台读取并刷新                     |
| 页面恢复为可见                               | 检查配置、权限与数据版本，并触发一次刷新以补偿休眠或冻结       |
| 任务或看板修改、导入、恢复、清空已成功持久化 | 任一仍在运行的待办页面观察到变化后排队刷新                     |
| 用户点击“立即刷新”                           | 跳过合并等待，刷新当前持久化数据                               |
| 多个待办页面打开                             | 协调为串行文件写入，队列不携带各页面的旧任务快照               |
| 页面仍在后台标签页                           | 正常运行时可继续处理事件，但浏览器节流、冻结和丢弃可能延迟导出 |
| 所有待办页面关闭                             | 已有文件保留；不承诺继续刷新                                   |
| 浏览器完全退出                               | 文件可被外部工具读取；不再执行同步逻辑                         |

实现建议采用约 500 毫秒合并连续事件，并设置约 2 秒的最大合并等待。
这些时间是页面正常运行时的调度目标，不是浏览器冻结或退出时的实时保证。
每次页面打开和手动刷新都重新导出，即使数据修订号未变化，也更新导出时间。
不要依赖 unload / beforeunload 完成最后写入。
若任务保存后立即关闭页面或退出浏览器，文件可能暂时落后；下一次打开时补齐。

### 权限、错误和停用

- 每次恢复连接先检查 readwrite 权限。权限有效才自动写入。
- 权限为 prompt / denied 时暂停刷新，显示“需要重新授权”，由用户点击按钮恢复，不在每次打开时强制弹窗。
- 用户恢复权限时必须保持调用所需的用户手势；权限恢复和文件选择不能等后台异步读取后再开始。
- 文件被删除、移动、替换、访问受限或磁盘写入失败时，显示相应失败状态与重试入口；不静默创建不同名字的文件。
- 文件句柄不支持、IndexedDB 不可用或跨标签页协调能力不可用时，明确显示此功能不可用；普通待办和现有手动备份仍可使用。
- “停止自动导出”与正在进行的写入串行处理。停止完成后，旧事件不得继续发起或提交写入。
- 停用保留文件及最后成功信息；可通过“重新连接”恢复已有文件，或选择另一个文件。
- 更换文件后不再更新旧文件；关闭、切换和失败都不得删除用户文件。
- 错误、成功状态和操作说明支持中英文；导出数据的字段名和用户内容不随界面语言变化。

## 对外文件契约 v1

UTF-8 JSON，顶层格式标识为 `ohmynewtabtodo.readonly`，`formatVersion` 为整数 `1`。
它与内部 `AppState.schemaVersion`、完整备份格式和扩展版本独立。

示例只使用合成数据：

```json
{
  "format": "ohmynewtabtodo.readonly",
  "formatVersion": 1,
  "source": {
    "instanceId": "d52d2589-f0e8-4b45-9972-f1abaf037f41",
    "appVersion": "0.4.0",
    "revision": 12
  },
  "exportedAt": "2026-11-04T08:00:00.000Z",
  "data": {
    "boardOrder": ["board-example"],
    "boards": {
      "board-example": {
        "id": "board-example",
        "title": "个人事项",
        "cardIds": ["card-example"],
        "isHidden": false,
        "createdAt": null,
        "updatedAt": null
      }
    },
    "cards": {
      "card-example": {
        "id": "card-example",
        "title": "整理阅读清单",
        "completed": false,
        "description": null,
        "labels": [],
        "tags": [],
        "priority": null,
        "dueDate": "2026-11-05",
        "dueTime": null,
        "createdAt": null,
        "updatedAt": null
      }
    }
  }
}
```

示例中的 appVersion 仅展示字段形态，实际始终取构建版本，不把本设计当作 0.4.0 已实现能力。

### 字段与兼容规则

- `source.instanceId` 是本浏览器配置内首次启用时生成并持久化的随机 UUID。
  不使用设备标识；停用、更换文件、任务清空、完整备份替换或恢复不改变它。
  卸载、清除该扩展本地数据或配置丢失后重新生成。
- `source.revision` 是本次读取的内部持久化修订号。比较修订号必须同时比较 instanceId。
  它也可能随非任务设置变化而增加，不等同于外部任务修改次数。
- `exportedAt` 是生成该快照的 UTC ISO 时间；仅在文件成功提交后对外可见。
  它不代表浏览器在线状态，也不能证明插件不存在尚未导出的更新；消费者不应仅凭时间较旧判定数据有变化。
- `boardOrder` 与各看板 `cardIds` 保留原顺序和 ID；消费端按它们遍历。
- 导出所有现存看板、任务，包括未列入 boardOrder 的看板和未被看板引用的任务。
  不为孤立对象补造 ID、归属或顺序。消费者可单独展示未归属对象。
- 只输出示例中列出的字段。标签保留字符串 id（有则输出）、text 和字符串 type（有则输出）；tags 只输出 text。
- 缺失或 null 的可选文本统一输出 null；缺失的 completed / isHidden 输出 false；缺失或 null 的 labels / tags 输出空数组。
  已存在的其他非预期字段类型属于投影失败，不默默转换为不同业务含义。
- 文本原样保留，不修剪标题、不重新解析描述、不生成 HTML、不翻译标签或优先级。
- dueDate / dueTime 保留原始本地日历日期与时间文本，不转换成 UTC 截止时间；不为无时间的日期补造时间。
  createdAt / updatedAt 保留原始字符串或 null，不为旧任务编造时间。
- 不输出书签、界面选项、主题、语言、恢复快照、导入历史、任务 history 或任何未列入白名单的未知字段。
  内部未知字段仍完整保留，本投影不对任务持久化结构作修复或迁移。
- 对象键顺序不属于契约，数组顺序属于契约。消费者忽略新增的未知字段；不兼容变更提升 formatVersion。
- 消费者应检查 format / formatVersion，并以一次读取解析出的完整文档为单位使用，不假定文件永远不变。

## 只读 CLI 与配套 Skill

用户要求同时提供 CLI 和配套 Skill，不提供 MCP。CLI 为按需启动的本机命令，直接读取上述 JSON 快照，不运行常驻服务，也不连接 Chrome 内部存储。使用 Node.js 22.12+，随项目分发；命令名暂定 `omntt`，以发布时文档为准。

- `boards` 列出全部看板；`tasks` 列出任务，支持 `--status pending|completed|all`、`--board <id>`、`--due today`；`task <id>` 返回单项；`status` 返回格式版本、来源、修订号和导出时间。
- `--file <path>` 指定文件，优先于环境变量 `OMNTT_FILE` 和用户配置文件；首次使用须由用户提供路径，文件选择器不会向 CLI 自动泄露完整路径。配置命令保存路径而不复制待办内容。
- 所有查询支持 `--json`：标准输出只输出可解析 JSON，错误写标准错误并返回非零退出码。文件缺失、无权限、JSON 损坏、版本不支持、ID 不存在均明确报错，不伪造空列表。
- 日期按执行 CLI 的本地日历筛选，保留文件中的原始日期与时间；无截止日期或无法解析的日期不匹配 today。CLI 仅读取完整快照，关闭浏览器后仍读取上次成功导出的数据；导出时间不等于在线状态或新鲜度保证。
- 配套可发现的 Codex Skill 说明路径配置、查询命令、JSON 输出和快照时效边界；只做读取，不把本地内容发送到其他服务，也不自动修改待办。Skill 及 CLI 在运行环境中必须能访问该文件，远程隔离环境需另行提供文件访问方式。
- 随项目提供 Skill 安装说明，默认不修改用户全局配置；验证命令使用合成快照，覆盖参数、路径优先级、筛选、状态、错误、只读和格式版本。CLI、Skill、插件可分别更新，文件格式是共同契约。

## 存储与职责边界

任务数据继续使用现有 chrome.storage.local / background / repository；后台仍是任务状态的唯一写入者。
导出入口在页面端运行，但每次实际写入前都通过 client.readState 从后台读取最新持久化状态，不能使用 React 的乐观页面快照。
任务保存成功与导出成功是两件事，不能互相回滚或混用成功提示。

文件句柄不能用 JSON 写入 chrome.storage.local；使用扩展同源 IndexedDB 保存句柄、启用配置、配置代数、instanceId 和最后导出结果。
这里只保存文件连接元数据，不迁移任务数据库，不把任务副本另存为第二个内部数据源。
这些元数据不进入完整备份、旧格式导出或恢复点。导入其他备份不偷偷开启文件访问或修改连接目标。

首次配置、配置切换、停用、状态更新和文件写入通过同一个同源 Web Lock 串行处理。
文件选择器和需用户手势的授权操作在锁外发起，结果交回锁内时检查配置代数；过期结果不得复活旧配置。
配置与状态变化通知其他页面；实现可用 BroadcastChannel，不能仅依赖某个设置面板一直挂载。
锁覆盖文件读取检查、后台状态读取、投影、完整文件写入和成功元数据更新。

每次写入在锁内读取当前配置和当前后台状态，而不是把旧快照排入队列。
若写入期间又收到持久化变化，标记待处理；完成后再次读取最新修订号，必要时继续刷新。
页面崩溃后锁由浏览器释放，其他页面或下次打开可继续工作；不依赖永久内存 leader。

同源锁只协调同一浏览器配置内的页面，不是操作系统全局文件锁。
第一版要求每个浏览器配置使用不同文件，不支持多个配置或浏览器同时向同一文件写入。
更换目标或初次连接发现它是其他 instanceId 的本接口文件时，需要明确的接管确认。
正常自动写入发现目标变成其他 instanceId 时暂停并报告，不能静默覆盖。
此检查不能防止不受控外部程序的同时写入，文档必须说明外部工具只读文件。
非空且不是本接口格式的文件（包括普通备份或损坏文件）一律拒绝，绝不覆盖；空文件可作为新快照。已连接文件被替换成非接口文件时暂停导出并报错。

## 完整写入与失败恢复

用 FileSystemWritableFileStream 一次生成完整 JSON；write 后必须等待 close 成功，之后才记录成功。
利用该 API 在 close 时提交变更的行为，不用先截断目标文件的普通写法。
写入失败尽力 abort，保留已有成功记录并单独记录当前失败；不宣称新版本已导出。
成功写出但元数据更新失败时显示状态保存错误，下次刷新从真实文件与后台状态恢复，不回滚业务数据。
不承诺断电级持久性，不把浏览器 API 的 close 成功描述为磁盘 fsync 保证。

权限失败等待用户恢复。其他失败保留待处理标志，在下次页面打开、页面可见或手动重试时刷新；
不进行无限紧密重试，不以连续弹窗打断编辑。磁盘失败不能静默回退到下载目录。
配置持久化损坏时停用连接并提示重新选择，不能猜测用户曾授权的路径。

## 平台验证与交付边界

现有插件最低 Chrome 为 120。第一版不为此功能提高整个插件的最低版本，使用能力与权限检测。
Chrome 122 起的持久授权可改善重开体验；旧版本或用户只允许一次时，允许显示恢复授权入口。
必须在正式打包的 chrome-extension:// 新标签页来源上验证文件选择、句柄恢复与写入，
不能仅凭 Vite 网页演示或通用 API 文档判定扩展场景已通过。
开发网页预览不自动连接正式扩展的文件；该设置明确只在正式扩展中启用。
不新增 downloads、nativeMessaging、网络主机或所有站点权限。

实现前用合成文件核实目标桌面 Chrome 的扩展页面能力和持久授权行为。
若真实扩展场景无法满足授权后固定文件更新，报告阻碍并返回方案选择，不能自行添加桥接程序或下载权限。
真实系统选择器、浏览器重启与权限持久化的人工验证和模拟适配器测试分别记录，不能相互冒充。

- 浏览器流程：正式扩展开启/停用、页面重开刷新、已完成/隐藏任务输出、跨标签页更新、

  备选方案的相对下载路径、覆盖行为和 downloads 权限。
