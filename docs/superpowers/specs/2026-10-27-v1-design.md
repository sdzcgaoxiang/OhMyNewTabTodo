# OhMyNewTabTodo 本地第一版设计

依据：用户已选定熟悉的看板交互、能力尽可能与原版一致、旧文件兼容；明确推迟跨设备同步，并要求尽量沿用参考实现的设计继续执行。独立实现，不复制闭源代码和素材。

## 方案与决策

已讨论 IndexedDB 与 chrome.storage.local；按用户“尽可能与参考源码设计一致”的取向，采用 React + JavaScript 模块、原版 boards/cards/boardOrder 数据结构、独立 storage API 封装和 chrome.storage.local。不使用 IndexedDB，不实现跨设备同步。

一处必要调整：以单个 app_state 记录保存完整版本化状态，而非逐对象写入；消除缺失 remove 的残留与分阶段导入。所有修改发给扩展 service worker，串行读取最新状态、应用操作、持久化后返回。页面监听 storage.onChanged。对象编辑带旧对象基线，冲突拒绝并保留表单；导入/恢复带预览版本号，过期预览必须重新确认。不把保存失败表现为成功。

## 数据与模块边界

AppState = {schemaVersion:1,revision:number,data:{boards,cards,boardOrder},bookmarks:[],options:{},theme:'light'|'dark',backups:[],imports:[]}; backups 为最多 3 份不递归的恢复快照。保持原版对象字段及未知字段，编辑采用补丁。时间使用原版日期/时间文本语义。

- model.js：默认值、纯函数操作、引用一致性、冲突检测。
- transfer.js：原版与完整备份解析、预览、合并/替换、旧格式与完整格式导出。
- repository.js：可注入 storage area 的读取与串行操作，错误传播。
- background.js：运行时消息路由及打开新标签页；不负责界面。
- client.js：页面消息与存储订阅。
- React components：看板、卡片、表单、设置、书签、导入导出。

## 导入与导出

旧格式顶层 id/appVersion/bookmarks/boardOrder/boards/cards。bookmarks 缺失按空数组。旧 ID、空数组与未知字段保留；不截断内容；对象类型/ID/引用非法时在写入前给出明确错误。未列入顺序的看板必须在预览中列出，可选择恢复到列表或保留原顺序且保留数据；孤立卡片同样保留并报告。不能自动判定它们应删除。

第一版提供“合并（相同 ID 相同内容跳过，内容不同报冲突）”“替换”“作为副本”三种模式，默认合并。替换需确认；导入前生成恢复点。完整备份保存任务、书签、设置、主题和未知业务字段，不携带恢复点的递归历史；原版格式导出明确缺少设置。重复同一文件合并不得重复添加。JSON 文件上限 5 MiB，超限明确失败。

## 界面与能力

横向看板、顶部与底部加卡、看板排序、卡片跨列拖拽；同时提供移动按钮作为可访问性替代。看板标题编辑、隐藏/显示和删除确认；卡片增删改、复制、详情、完成、优先级、两个标签入口、日期时间。原版默认选项、深浅主题、常用链接抽屉、四个搜索引擎入口、日期时间时钟、12/24 小时与固定/短显。保留完成项隐藏/变暗、紧凑模式、描述与链接显示选项。使用独立视觉标识，系统字体，不访问作者的统计/反馈/通知服务。

初始为空看板状态，不默认注入演示任务或外部链接。全中文主界面，保留英文项目名。任何字符串渲染为文本；仅 http/https URL 可成为外链。

## 验收

数据测试：缺 bookmarks、残留看板、25 个书签、未知字段、往返、重复合并、冲突、删除持久化、配额错误、并发修改、预览过期、恢复点、未来 schema 拒绝。

浏览器测试：独立 Chromium 临时配置加载新扩展，验证创建/编辑/复制/完成/移动/删除、重启页面、多标签页、实际文件导入/下载、错误预览、设置/主题与恢复；不触碰用户 Chrome 配置。
