# v0.1.0 验收与审查记录

日期：2026-10-27。目标是本机可使用、能可靠迁移 NewTabTodo 0.2.0 文件的独立开源第一版。

## 验证方式

- `npm run check`：源码格式检查、26 项 Node 测试、生产构建、16 项实际 Chromium 扩展验收。
- `npm run package`：仅允许扩展入口、资源、manifest 和许可证进入压缩包；校验 ZIP 完整性并生成 SHA-256。
- Node 日期测试同时在默认时区与 `America/New_York` 下通过，覆盖本地跨午夜和夏令时相邻日期。
- 在独立临时 Chromium 配置内检查了合成看板和导入/导出抽屉截图；README 图片只使用人工样例。
- 用户提供的原始文件仅在本机做只读解析及完整/旧格式往返比较：3 个看板、7 张卡片及未显示看板均保留。原文件和内容未纳入仓库，也未导入日常 Chrome。

浏览器覆盖创建、编辑、复制、完成、删除、刷新后持久化、原生拖拽和按钮移动、看板排序、多标签页冲突、隐藏设置、主题、常用链接、实际文件选择与下载、替换/恢复、跨午夜日期刷新以及以下回归。

## 决策与验证边界

- 保留原业务结构，采用单个 `chrome.storage.local` 记录和后台串行操作。这样减少原版多键半提交和删除残留，代价是每次保存重写完整状态、恢复点共同占用本地配额；未来大数据量需要重新测量。
- 按用户后续授权公开 GitHub 源码及版本包，替代最初“仅本地实现”的范围。私人参考目录及原版闭源实现不进入提交历史；Chrome Web Store 发布不在本期内。
- 发布包、CI、截图与文档由主实现任务验证，独立审查只评价其指定的代码版本；CI 的远程运行结果以仓库 Actions 为准。
- 兼容证据集中在已审计的 0.2.0 格式；没有承诺所有历史版本。空缺字段只能按可验证规则兼容，无法还原旧导出器已经删掉的信息。
- 界面为独立实现，保留熟悉交互而非逐像素复刻。已验证原生对话框、标签、按钮替代拖拽等路径，未完成专业无障碍全面审计。
- 仓储测试验证串行写入、保存失败、重新实例化读取和未来 schema 拒绝；没有穷举 service worker 每个指令位置崩溃、所有浏览器配额或升级时仍打开的旧页面。失败时不得伪装成功，升级前应导出备份。
- 跨设备同步、账号与后端明确排除；同一浏览器多页面一致性已在验收范围内。这不等于跨设备冲突协议。

第一版发放的是手动加载的扩展包；Chrome 最低版本声明与真实测试版本范围见 README。
